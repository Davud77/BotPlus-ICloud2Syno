# Публикация обновлений

Приложение использует [Sparkle 2.10.0](https://sparkle-project.org/documentation/) через Swift Package Manager. Версия и контрольная сумма бинарной зависимости зафиксированы в Package.resolved. Лицензия: [Sparkle-LICENSE.txt](../ThirdParty/Sparkle-LICENSE.txt).

Каталог: `https://raw.githubusercontent.com/Davud77/BotPlus-ICloud2Syno/main/appcast.xml`. `SURequireSignedFeed` требует подпись каталога; `SUVerifyUpdateBeforeExtraction` требует проверку подписи архива до извлечения. Открытый ключ находится в `Resources/Info.plist`. Настройки TLS сервера NAS не используются обновлятором.

Закрытый Ed25519-ключ создан в macOS Keychain с account `com.synologyphotosync.app`. Его нет в исходниках и артефактах. Не создавайте новый ключ для каждого релиза: уже установленные приложения доверяют текущему открытому ключу. Резервное копирование и перенос ключа выполняйте по [инструкции Sparkle](https://sparkle-project.org/documentation/#3-segue-for-security-concerns); не помещайте закрытый ключ в Git или общедоступные файлы.

## Новый релиз

1. Увеличьте CFBundleVersion и CFBundleShortVersionString в Resources/Info.plist и версии в generate_project.py. CFBundleVersion должен возрастать.
2. Выполните `swift test`, `python3 generate_project.py --check` и `./build.sh`.
3. Получите инструменты из официального дистрибутива Sparkle. Выполните `./make_appcast.sh /path/to/Sparkle/bin` на машине с ключом Keychain.
4. Создайте черновик GitHub Release с соответствующим тегом `v<версия>`. Загрузите **неизменённый** `SynologyPhotoSync-<версия>-arm64.zip` из build_output, DMG и SHA-256. ZIP без версии предназначен только для ручного скачивания.
5. Проверьте подпись каталога `sign_update --account com.synologyphotosync.app --verify appcast.xml`. Изменение подписанного XML после генерации недопустимо без повторной подписи.
6. Опубликуйте релиз. Затем отправьте appcast.xml в main, чтобы каталог никогда не указывал на ещё недоступный пакет. Проверьте скачивание архива по URL каталога и подписи до объявления релиза.

Нельзя переупаковывать ZIP после подписи. Сохраняйте symlink и права исполнения вложенных компонентов Sparkle. `codesign --verify --deep --strict` должен проходить для упакованного приложения.

## Работа приложения

Проверка запускается кнопкой в настройках. Автоматическая фоновая проверка и скрытая автоматическая установка отключены. Стандартный интерфейс Sparkle ведёт скачивание, проверку, установку и перезапуск; ошибки не приводят к выполнению неподтверждённого пакета.

Проверка заблокирована на время синхронизации. Если она началась между проверкой и установкой, установка откладывается до полного освобождения задачи; пауза сохраняет ожидание. В этот период приложение блокирует новые запуски синхронизации. Для установки в защищённую папку macOS может запросить системную авторизацию. Старый процесс не заменяется собственным shell-скриптом приложения.

Версии 1.2 и 1.3 не имеют Sparkle, поэтому первый переход на 1.4 требует установки DMG вручную. Для Developer ID и Apple notarization необходимы собственные сертификаты; подписи Sparkle их не заменяют.

## Проверка

XCTest проверяет отображение версии, откладывание/отмену установки и подписи правильным и неверным ключами. `Tools/UpdateSmokeTest.m` — дополнительный изолированный драйвер настоящего установщика Sparkle. Он принимает только одноразовое приложение с ID `com.synologyphotosync.update-test` внутри `/tmp/aphotos-update-e2e/`. Его нельзя направить на рабочую копию.

Скриншоты созданы отдельной Debug-сборкой с флагом `SCREENSHOT_PREVIEW` и отдельным bundle ID. В ней отключены синхронизация, чтение пароля Keychain и настоящей медиатеки, используются отдельные настройки и временная база. В обычных сборках этот режим выключен на этапе компиляции.
