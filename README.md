# SynologyPhotoSync

Версия 1.2.0. Приложение для строки меню macOS 13+ на Apple Silicon, Swift и SwiftUI. Release собирается только для arm64. Извлекает доступные PhotoKit оригиналы из Apple Photos и отправляет их в Synology Photos без перекодирования. Поддерживает фото, видео, пары Live Photo и добавление загруженных файлов в альбомы.

## Скачать

Готовый DMG для Apple Silicon: [последний релиз](https://github.com/Davud77/BotPlus-ICloud2Syno/releases/latest).
Откройте образ и перетащите приложение в Applications. Поддерживаются macOS 13+ и Mac с Apple Silicon.

В релизе приложены контрольные суммы SHA-256. Сборка подписана локальной ad-hoc подписью, без Apple notarization. Для собственного релиза с Developer ID используйте свою подпись и процедуру notarization.

## Сборка

Требуется Xcode с поддержкой Swift 5.9 или новее.

```sh
./build.sh
```

Результаты: `build_output/SynologyPhotoSync.zip`, `build_output/SynologyPhotoSync-<версия>-arm64.dmg` и файл SHA-256. DMG содержит приложение и ярлык Applications. Скрипт выводит путь к собранному `.app` во временном каталоге. Сборка и подпись выполняются вне iCloud/File Provider: метаданные этих папок могут мешать `codesign`. Распакуйте архив, например, в Applications.
Можно также открыть `SynologyPhotoSync.xcodeproj` и запустить схему `SynologyPhotoSync`. Для распространения на других Mac нужны собственная подпись Developer ID и notarization. Локальная сборка их не заменяет.

Отдельная упаковка готового приложения: `./package_dmg.sh /path/to/SynologyPhotoSync.app`. Образ проверяется `hdiutil verify`, приложение — `codesign --verify --deep --strict`.

Swift Package используется для проверки исходников и тестов; запускайте GUI из `.app`, чтобы macOS получила описание доступа к Photos из `Info.plist`.

## Подключение

1. Откройте настройки из строки меню.
2. Укажите конечный HTTPS-адрес DSM, например `https://nas.example.com:5001`. Допускается путь обратного прокси. HTTP, адреса с логином/паролем, query и fragment отклоняются. Перенаправления не выполняются: укажите конечный адрес.
3. Введите пользователя с правами на Synology Photos, пароль и при необходимости OTP. Нажмите «Проверить соединение». Пароль сохраняется в Keychain при этой операции.
4. Выберите источник, дату, пространство назначения и параметры альбомов. Запустите синхронизацию.

Проверка TLS включена по умолчанию. Для недоверенного сертификата есть явное исключение в настройках: оно отключает проверку подлинности сервера. Предпочтительно установить доверенный сертификат. ATS допускает динамические адреса NAS и это исключение, а клиент разрешает только HTTPS.

## Поведение и защита данных

- Пароли и OTP передаются в теле POST; SID — в Cookie-заголовке HTTPS-запроса. Секреты не включаются в URL. Для multipart это необходимо: сервер проверяет сессию до разбора тела. Ответы авторизации не записываются в журнал. Файлы и параметры не отправляются через HTTP redirect.
- Пароли привязаны к серверу и пользователю; сессии дополнительно привязаны к режиму проверки TLS. Keychain обновляется без предварительного удаления старого пароля.
- Операция считается успешной только после ответа Synology с положительным ID. Код 120, HTML от прокси, неполный JSON и отсутствие ID дают ошибку. Пропущенный сервером дубликат без ID требует проверки; приложение не заявляет, что он синхронизирован.
- Просроченная сессия допускает одну повторную авторизацию на операцию и регистрирует предупреждение. Повторное отклонение сессии, ошибки входа, доступа, параметров протокола и сети останавливают очередь. Доступ проверяется перед извлечением ресурсов из iCloud. HTTPS-соединения переиспользуются между запросами и загрузками.
- Параметры строк Synology Photos кодируются как JSON. Для дедупликации используется подтверждённый на NAS режим `ignore`; повторный запрос возвращает ID существующего файла.
- Разные снимки с одинаковым исходным именем получают разные устойчивые суффиксы. У пары Live Photo сохраняется общее базовое имя. Расширение отредактированной копии берётся из её собственного ресурса.
- Фото и видео копируются на диск без декодирования. Multipart собирается блоками по 1 МиБ, затем загружается из файла. RAM не растёт пропорционально размеру медиафайла. На диске требуется место для извлечённых ресурсов и multipart-копии.
- Временные ресурсы находятся в отдельных каталогах с правами `0700`; multipart и база получают `0600`. Временные файлы удаляются при завершении операции, включая обычные ошибки и отмену. После аварийного завершения процесса очистка не гарантируется.
- Сканирование и подсчёт альбомов выполняются вне главного потока. События Photos объединяются с задержкой 750 мс; изменения во время передачи вызывают дополнительное сканирование.
- Запускается один цикл синхронизации. Изменение настроек назначения и сброс базы блокируются на время передачи. Пауза действует между файлами/альбомами; текущая операция завершается. Пауза учитывается также перед следующим ресурсом пары Live Photo и между извлечением и отправкой. Сетевая передача поддерживает отмену. PhotoKit `writeData` не предоставляет отмену: остановка ждёт завершения текущего извлечения, после чего загрузка не начинается.
- JSON-база сохраняется атомарно. Ошибка сохранения не оставляет файл отмеченным успешным в памяти. Повреждённая база не перезаписывается автоматически.
- Альбомы получают только уже подтверждённые ID в выбранном пространстве, с учётом источника и даты. Для общего пространства используется семейство `SYNO.FotoTeam`. Просмотр альбомов учитывает страницы; добавление выполняется пакетами до 500 уникальных ID. После ошибки списка альбом не создаётся вслепую.

## Предварительная сверка с NAS

Перед каждой выгрузкой приложение обходит все вложенные папки выбранных пространств Synology Photos и читает все страницы каталога. В меню и настройках показываются:

- сколько объектов и папок просмотрено на NAS;
- сколько снимков из выбранной медиатеки уже подтверждено на NAS;
- сколько снимков нужно догрузить и сколько из них отправлено в текущем проходе.

Учитываются выбранные источник, дата, пространство, Live Photo и отредактированные копии. Полный Live Photo считается найденным только с необходимыми ресурсами. Если часть ресурсов уже есть, передаются только недостающие. Сопоставленные ID сохраняются для синхронизации альбомов.

Ранее подтверждённые ID проверяются по свежему каталогу. Сохранившаяся локальная запись больше не скрывает удалённый с NAS файл: он возвращается в очередь. Для имён, созданных этим приложением, используется устойчивый суффикс идентификатора Photos. У старых файлов рассматриваются оригинальные и безопасные транслитерированные имена, затем проверяются размер и SHA-256 исходных байтов. Одного совпадения имени или даты недостаточно.

**Первый проход старых файлов может быть долгим:** PhotoKit извлекает кандидат из локальной/iCloud-медиатеки, а оригинал с NAS скачивается во временный файл для хеширования. Подтверждения ресурсов сохраняются; последующие проходы проверяют их ID и имена по каталогу. Если файлы на NAS произвольно переименованы и локальные подтверждения потеряны, приложение не объявляет их совпадением без доказательства; возможна передача для проверки серверной дедупликацией.

Ошибка каталога или сравнения останавливает проход с ошибкой, а не превращает непрочитанный каталог в «пустой». Пауза и отмена работают во время сверки. Изменение NAS одновременно с обходом может потребовать следующего прохода: API не предоставляет транзакционный снимок каталога.

## Статусы сеанса

- **Синхронизация завершена**: обработана вся очередь файлов и альбомов, нет ошибок, оставшихся записей ошибок или предупреждений.
- **Приостановлено**: сеанс остаётся активным. Даже завершение последней текущей передачи не меняет статус до возобновления.
- **Остановка синхронизации… / Синхронизация отменена**: отмена отображается сразу, затем сохраняется как отдельный итог. Поздние callbacks не заменяют её успехом.
- **Требуется внимание**: были предупреждения (включая восстановленную сессию) или остались необработанные задачи.
- **Ошибка синхронизации**: есть ошибки текущего прохода или непогашенные записи ошибок.

После отмены, ошибки или итога с предупреждениями фоновый запуск по событиям Photos приостановлен до ручного старта. Журнал сохраняет причины. Процент обозначает долю обработанной очереди и сам по себе не означает успех.

## Обновление со старой версии

Старая база `~/Library/Application Support/SynologyPhotoSync/state.json` сохраняется. В ней не указан сервер или пользователь, поэтому она не используется как доказательство загрузки в новое назначение. Базы `state-<hash>.json` автоматически дополняются подтверждениями отдельных ресурсов; формат предыдущих версий читается без сброса. Они разделены по серверу, пользователю, пространству, настройкам Live Photo и отредактированных копий.

При переходе с самой первой версии введите пароль заново и проверьте соединение: старые общие записи Keychain не переиспользуются автоматически. Новый формат имён и отдельная база могут привести к повторной выгрузке ранее загруженных файлов. Сначала проверьте небольшую выборку по дате.

## Проверка

```sh
swift test
./build.sh
```

По умолчанию тесты используют временные каталоги и подменённый `URLProtocol`; к NAS и медиатеке они не обращаются. `LiveSynologyTests` запускается отдельно и только при наличии переменных окружения `SYNOPHOTOS_LIVE_URL`, `SYNOPHOTOS_LIVE_USER`, `SYNOPHOTOS_LIVE_PASSWORD`. Дополнительный флаг `SYNOPHOTOS_LIVE_FULL_SCAN=1` разрешает отдельный тест полного чтения каталога. Тест передачи создаёт один диагностический PNG и альбом, проверяет дубликат и очищает только собственные объекты по подтверждённым ID и точным именам. Пароли в исходниках, fixture-файлах и Keychain тест не сохраняет. Проверяются HTTP/JSON-ошибки, границы повторного входа, подтверждение ID, кодирование секретов, бинарная целостность multipart, имена файлов, сохранение и разделение базы, обработка повреждений и счётчики интерфейса.

Для полного испытания нужен собственный тестовый NAS и небольшая медиатека: обычное фото, видео, Live Photo, отредактированный ресурс, два разных файла с одинаковыми именами и альбомы в обоих пространствах. Проверьте повторный запуск, истечение SID, неверный OTP, разрыв сети и остановку во время iCloud/загрузки. Побитовую целостность на NAS следует сравнить отдельно по хешам оригиналов.

## Ограничения

- Используемые методы Synology Photos требуют проверки с конкретной версией DSM/Photos. На тестовом NAS отдельно проверены полный обход личного пространства, чтение оригинала и SHA-256, вход, загрузка, дедупликация и добавление в альбом. Это не заменяет проверку больших файлов, Shared Space и Live Photo на конкретном NAS.
- «Общие альбомы iCloud» определяются через PhotoKit `.typeCloudShared`. Это не отдельная поддержка iCloud Shared Photo Library. Ресурсы общих альбомов могут отличаться от оригиналов владельца.
- Это добавочная выгрузка. Удаления и последующие изменения уже отмеченных файлов не зеркалируются. Ошибка выбранной отредактированной копии оставляет весь объект в очереди повторной попытки.
- Live Photo загружается двумя запросами; транзакции между ними нет. При обрыве возможна частичная пара. Объединение пары и дедупликация зависят от Synology Photos.
- Встроенные метаданные сохраняются в извлечённых байтах, но отображение дат, HDR, GPS, RAW и Live Photo определяется сервером. SHA-256 оригинала проверен для диагностического PNG; остальные форматы требуют отдельной проверки.
- Приложение работает с hardened runtime, без App Sandbox. Распространяемый релиз требует отдельного аудита подписи, разрешений, интеграции и интерфейса на поддерживаемых версиях macOS.
